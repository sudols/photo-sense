## Phase 1: Project Scaffolding

**Goal:** Bootable React app with shadcn/ui, Tailwind, and dev server running.

### Steps

1. **Create Vite project**
   ```bash
   npm create vite@latest frontend -- --template react-ts
   cd frontend
   npm install
   ```

2. **Install core dependencies**
   ```bash
   npm install react-router-dom axios
   ```

3. **Install and configure Tailwind CSS**
   ```bash
   npm install -D tailwindcss @tailwindcss/vite
   ```
   - Add Tailwind plugin to `vite.config.ts`
   - Add `@import "tailwindcss"` to `src/index.css`
   - Remove all default Vite CSS

4. **Initialize shadcn/ui**
   ```bash
   npx shadcn@latest init
   ```
   - Style: Default (or New York)
   - Base color: Slate (or any)
   - CSS variables: yes
   - This creates `components.json`, `src/lib/utils.ts`, and `src/components/ui/` directory

5. **Add shadcn components**
   ```bash
   npx shadcn@latest add button card input label dialog dropdown-menu avatar separator skeleton sheet badge alert
   ```

6. **Create directory structure**
   ```
   src/
   ├── api/            # Axios instance + API functions
   │   ├── axios.ts    # Configured axios with JWT interceptor
   │   ├── auth.ts     # login, register, refreshToken
   │   ├── photos.ts   # upload, list, get, delete, search
   │   └── persons.ts  # list, get, rename, delete, merge
   ├── components/     # shadcn/ui (auto-generated) + custom
   │   └── ui/         # shadcn components live here
   ├── pages/          # One file per page
   │   ├── LoginPage.tsx
   │   ├── RegisterPage.tsx
   │   ├── HomePage.tsx
   │   ├── PhotoDetailPage.tsx
   │   ├── PeoplePage.tsx
   │   ├── PersonDetailPage.tsx
   │   └── SearchPage.tsx
   ├── lib/
   │   └── utils.ts    # cn() helper (auto-generated by shadcn)
   ├── App.tsx          # Routes + auth guard
   ├── main.tsx         # Entry point
   └── index.css        # Tailwind imports + shadcn CSS vars
   ```

7. **Verify** — `npm run dev` should show a blank page with no errors at `http://localhost:5173`

### Deliverable
- Bootable Vite + React + TypeScript + Tailwind + shadcn/ui app
- Empty page rendering at localhost:5173

## Phase 2: Django CORS Fix

**Goal:** Make the backend accept requests from the React dev server in production.

### Steps

1. **Edit `backend/photosense/settings.py`** — Replace:
   ```python
   CORS_ALLOW_ALL_ORIGINS = DEBUG
   ```
   With:
   ```python
   if DEBUG:
       CORS_ALLOW_ALL_ORIGINS = True
   else:
       CORS_ALLOWED_ORIGINS = os.environ.get("CORS_ALLOWED_ORIGINS", "").split(",")
   ```

2. **For local development** — `DEBUG=True` means all origins allowed, no change needed.

3. **For production demo** — Set environment variable `CORS_ALLOWED_ORIGINS=https://your-frontend.onrender.com,http://localhost:5173`

4. **Verify** — From browser dev console, `fetch("http://localhost:8000/api/photos/")` should not throw CORS error (with Django running).

### Deliverable
- Backend accepts cross-origin requests from React frontend in both dev and prod

## Phase 3: API Layer

**Goal:** All 13 API endpoints callable from typed TypeScript functions with automatic JWT handling.

### Files

#### `src/api/axios.ts`
- Create axios instance with `baseURL` from env var (default: `http://localhost:8000`)
- **Request interceptor:** Read `access` token from localStorage, attach `Authorization: Bearer <token>` header
- **Response interceptor (401):**
  1. If response is 401 and a refresh token exists in localStorage
  2. Call `POST /api/auth/refresh/` with the refresh token
  3. On success: update `access` in localStorage, retry original request
  4. On failure: clear localStorage, redirect to `/login`
- Export the configured axios instance

#### `src/api/auth.ts`
```typescript
login(username: string, password: string)
  // POST /api/auth/login/ with {username, password}
  // On success: store {access, refresh} in localStorage
  // Returns: {access, refresh}

register(email: string, password: string)
  // POST /api/auth/register/ with {email, password}
  // Returns: {message}

refreshToken(refresh: string)
  // POST /api/auth/refresh/ with {refresh}
  // Returns: {access}

logout()
  // Clear localStorage
  // Redirect to /login
```

#### `src/api/photos.ts`
```typescript
listPhotos()
  // GET /api/photos/
  // Returns: Photo[]

getPhoto(id: string)
  // GET /api/photos/{id}/
  // Returns: Photo

uploadPhoto(file: File)
  // POST /api/photos/upload/
  // Content-Type: multipart/form-data with {file}
  // Returns: Photo

deletePhoto(id: string)
  // DELETE /api/photos/{id}/
  // Returns: void

searchPhotos(query: string)
  // GET /api/photos/search/?q={query}
  // Returns: Photo[]
```

#### `src/api/persons.ts`
```typescript
listPersons()
  // GET /api/persons/
  // Returns: Person[] (photos field is null)

getPerson(id: string)
  // GET /api/persons/{id}/
  // Returns: Person (photos field is Photo[])

renamePerson(id: string, name: string)
  // PATCH /api/persons/{id}/ with {name}
  // Also sets is_unnamed to false
  // Returns: Person with photos

deletePerson(id: string)
  // DELETE /api/persons/{id}/
  // Returns: void

mergePerson(fromId: string, intoId: string)
  // POST /api/persons/{fromId}/merge/ with {merge_into_id: intoId}
  // Returns: Person (the merged-into person)
```

### TypeScript Types

Define in a shared `src/api/types.ts`:
```typescript
interface Photo {
  id: string;
  s3_key: string;
  url: string;              // presigned S3 URL
  face_ids: string[];
  detected_text: string[];
  detected_faces: DetectedFace[];
  faces_count: number;
  analyzed_at: string | null;
  created_at: string;
  updated_at: string;
}

interface DetectedFace {
  face_id: string;
  bounding_box: BoundingBox;
  confidence: number;
}

interface BoundingBox {
  Left: number;
  Top: number;
  Width: number;
  Height: number;
}

interface Person {
  id: string;
  name: string;
  face_id: string;
  face_ids: string[];
  bounding_box: BoundingBox | null;
  thumbnail_s3_key: string;
  thumbnail_url: string | null;  // presigned URL or null
  is_unnamed: boolean;
  created_at: string;
  updated_at: string;
  photos: Photo[] | null;        // null on list, Photo[] on detail
}
```

### Deliverable
- All 13 API endpoints wrapped in typed TypeScript functions
- JWT auto-attach and auto-refresh working
- No page renders yet, but functions are callable from browser console

## Phase 4: Auth Pages + Routing

**Goal:** Login and register pages working, route protection in place, authenticated users land on home.

### Routes Setup (`src/App.tsx`)
```
/login          → LoginPage
/register       → RegisterPage
/               → HomePage        (protected)
/photos/:id     → PhotoDetailPage (protected)
/people         → PeoplePage      (protected)
/people/:id     → PersonDetailPage (protected)
/search         → SearchPage      (protected)
```

### Auth Guard
- In `App.tsx`, wrap protected routes in a component that checks `localStorage.getItem("access")`
- If no token, redirect to `/login`
- If token exists, render the route
- No need to validate token client-side — if it's expired, the axios interceptor will refresh it or redirect to login

### `src/pages/LoginPage.tsx`
- shadcn Card centered on page
- Form with email (Input) and password (Input type=password)
- "Login" Button → calls `login()` from `src/api/auth.ts`
- On success: `navigate("/")`
- On error: show error message below form (shadcn Alert or simple red text)
- Link to `/register` ("Don't have an account? Sign up")
- Page title: "PhotoSense"

### `src/pages/RegisterPage.tsx`
- Same layout as LoginPage
- Form with email and password + confirm password
- "Create Account" Button → calls `register()` from `src/api/auth.ts`
- On success: `navigate("/login")` with a "Account created! Please log in." message (can use URL param or state)
- On error: show error message
- Link to `/login` ("Already have an account? Log in")

### Layout
- Simple top navigation bar with: "PhotoSense" logo/text on left, "Logout" button on right
- Navigation tabs: "Photos" (→ `/`), "People" (→ `/people`), "Search" (→ `/search`)
- Use shadcn Button variants for nav links
- Auth pages (login/register) do NOT show the navbar

### Deliverable
- User can register, login, and be redirected to home page
- Protected routes redirect to login when not authenticated
- Logout clears token and redirects to login

## Phase 5: Home Page (Photo Gallery)

**Goal:** Photo grid with date grouping and upload functionality.

### `src/pages/HomePage.tsx`

#### Layout
1. **Header area:** "Photos" title + Upload Button (top right)
2. **Upload area:** When upload button is clicked, open file picker (single file). Show loading spinner during upload (3-7 seconds). On success, refresh the photo list.
3. **Photo grid:** Photos grouped by date, each group has a date heading followed by a uniform grid of square thumbnails.

#### Date Grouping Logic
```
- Parse photo.created_at
- Group by calendar date (YYYY-MM-DD)
- Display labels:
  - Today's date → "Today"
  - Yesterday → "Yesterday"
  - Older → "April 16, 2025" (MMMM D, YYYY format)
- Sort groups newest-first
- Within each group, photos are already sorted by -created_at from backend
```

#### Photo Grid Rendering
- CSS Grid: `grid-cols-3 sm:grid-cols-4 md:grid-cols-6 lg:grid-cols-8`
- Each cell: square aspect ratio (`aspect-square`), `object-cover` on the `<img>`
- `<img src={photo.url}>` — presigned URL from API, works directly
- Click on photo → `navigate(`/photos/${photo.id}`)`
- Hover effect: slight opacity change or border highlight

#### Upload Flow
1. Click "Upload" button → hidden `<input type="file" accept="image/*">` is triggered
2. On file select: call `uploadPhoto(file)` from API layer
3. Show loading state: replace the upload button with a spinner or progress text ("Uploading...")
4. On success: prepend new photo to the list (or re-fetch entire list)
5. On error: show error toast/alert

#### Data Fetching
```typescript
const [photos, setPhotos] = useState<Photo[]>([]);
const [loading, setLoading] = useState(true);

useEffect(() => {
  listPhotos().then(setPhotos).finally(() => setLoading(false));
}, []);
```

#### Empty State
- When no photos: show centered text "No photos yet. Upload your first photo!" with upload button

### Deliverable
- Photo grid showing all user photos grouped by date
- Upload works and photo appears in grid
- Click photo navigates to detail page
- Loading and empty states handled

1. Click "Merge" button
2. Dialog opens with a searchable/selectable list of other persons
3. The list comes from `listPersons()` (already available from people page, or re-fetch)
4. Select target person → confirm merge
5. Call `mergePerson(currentId, targetId)`
6. On success: navigate to `/people/{targetId}` (the surviving person)

## Key Decisions Log

| Decision | Choice | Rationale |
|----------|--------|-----------|
| State management | useState/useEffect | Demo scale, no complexity needed |
| Data fetching | Plain axios calls in useEffect | No TanStack Query needed at 2-3 users |
| Component library | shadcn/ui | Copy-paste components, looks professional, reduces CSS work |
| CSS | Tailwind | Required by shadcn, rapid development |
| Routing | React Router v6 | Standard React routing |
| Photo grid layout | Uniform CSS Grid | Matches Flutter app, simplest to implement |
| Auth storage | localStorage | Not secure for production, perfectly fine for demo |
| CORS fix | Environment variable based | Works in both dev (wildcard) and prod (specific origins) |
| Pagination | None | 2-3 users, trivial data, not needed |
| Upload feedback | Loading spinner + disabled button | Simple, works for synchronous 3-7s upload |
| No image caching | Presigned URLs refresh on every request | URLs expire after 7 days; simpler to just re-fetch |
